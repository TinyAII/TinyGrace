# TinyGrace · 有限死亡保护

> 前 N 次死亡不掉落，用完之后恢复正常。
> **单 jar 支持 1.14 ~ 26.x**，零依赖，不需要任何前置插件。

---

## 特性

| 功能 | 说明 |
| --- | --- |
| 🛡 **配额制保护** | 每个玩家有 N 次「死亡不掉落」机会，用完恢复正常 |
| 🎁 **额外次数** | 管理员可以给单个玩家加次数（活动奖励、补偿） |
| 🎒 **完整保留** | 死亡时保留背包、等级与经验 |
| 🔀 **三个开关** | 全局 / 个人 / keepInventory 世界豁免，互不干扰 |
| ⚠️ **两级提醒** | 剩 3 次、1 次时黄色提醒；用完后每次死亡红色提醒 |
| 💾 **数据跟人走** | 存在玩家自身（PDC），**不建任何数据文件** |
| 📦 **零依赖** | 不需要 Vault / PlaceholderAPI / 任何前置 |

## 安装

1. 把 `TinyGrace-x.x.x.jar` 放进 `plugins/`
2. 重启服务器
3. 进游戏敲 `/tg info`

控制台应该出现：

```
[TinyGrace] TinyGrace v1.0.0 —— 有限死亡保护
[TinyGrace]  支持范围: 1.14 ~ 26.x（Java 8 字节码, api-version 1.14）
[TinyGrace]  全局开关: 开启
[TinyGrace]  基础保护: 10 次 | 新玩家额外: 0 次
[TinyGrace]  临界预警: [3, 1]
[TinyGrace]  keepInventory 世界: 不消耗配额
```

## 指令

主命令 `/tinygrace`（别名 `/tg`、`/保护`）

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `/tg info [玩家]` | 查看剩余保护次数、已用次数、死亡次数 | tinygrace.use |
| `/tg on` / `/tg off` | 开关**自己**的死亡保护 | tinygrace.use |
| `/tg deaths [玩家]` | 查看累计死亡次数 | tinygrace.use |
| `/tg set <玩家> <次数>` | 设置某人的额外保护次数 | tinygrace.admin |
| `/tg add <玩家> <次数>` | 增加某人的额外保护次数 | tinygrace.admin |
| `/tg reset <玩家>` | 清空某人已用次数（重新发放配额） | tinygrace.admin |
| `/tg global <on\|off\|toggle>` | 切换全局保护 | tinygrace.admin |
| `/tg reload` | 重载配置 | tinygrace.admin |

> ⚠️ `set / add / reset` **只能对在线玩家使用** —— 数据存在玩家身上，人不在线改不了。
> 要批量发次数，建议等他上线。

## 权限

| 节点 | 默认 | 作用 |
| --- | --- | --- |
| `tinygrace.use` | true | 查看自己、开关自己 |
| `tinygrace.admin` | op | 查看/修改他人、全局开关、重载 |
| `tinygrace.unlimited` | false | **无限保护**，死亡永不消耗次数 |

## 配置

```yaml
enabled: true                    # 全局开关

protection:
  base: 10                       # 每人默认保护次数
  default-bonus: 0               # 额外发放（可给全员补偿）
  warn-at: [3, 1]                # 剩余多少时黄色提醒
  keep-inventory-consumes: false # keepInventory 世界是否也扣次数
  keep-level: true               # 是否保留等级与经验
  warn-exhausted: true           # 用完后每次死亡是否红色提醒

messages:
  warn: "&e⚠ 你只剩 &f{0} &e次死亡保护了 &7(基础剩余 {1} / 额外 {2})"
  exhausted: "&c✖ 你的死亡保护次数已用完，本次死亡掉落了物品 &7(用 /tg info 查看)"
  switch-on: "&a✔ 已开启你的死亡保护（当前剩余 &f{0} &a次）"
  switch-off: "&7已关闭你的死亡保护（死亡将正常掉落）"
```

颜色码用 `&`，占位符 `{0}` `{1}` `{2}`。

### `keep-inventory-consumes` 为什么要单独一个开关

有些服的世界本来就开了 `keepInventory=true`（比如创造服、小游戏世界）。
那种世界死亡本来就不掉东西，如果还扣玩家次数，玩家会觉得「我什么都没掉，凭什么扣我一次」。

所以默认 `false`：**这类世界不消耗次数**。想强制扣就改 `true`。

## 工作原理

### 判定顺序

```
1. 全局开关关                    → 不处理，正常掉落
2. 世界已开 keepInventory 且配为不消耗 → 不处理（本来就不掉）
3. 玩家个人开关关                → 不处理
4. 记一次死亡（统计用）
5. 有 tinygrace.unlimited 权限   → 直接保护，不扣次数
6. 没有剩余次数                  → 不处理 + 红色提醒
7. 有剩余次数 → 扣一次 → 保留背包/等级/经验 → 临界提醒
```

### 为什么用两个计数器

插件在玩家身上存两类数据：

| 键 | 含义 | 用途 |
| --- | --- | --- |
| `deaths` | 累计死亡次数 | **只做统计**，管理员看活跃度 |
| `used` | 已消耗的保护次数 | **只做判定**，剩余 = `base + bonus - used` |

如果只用一个计数器，配额用完它还会继续涨；管理员半年后把 `base` 从 10 调到 20，
老玩家会突然得到「20 − 过去死了 50 次」= 负数，或者反过来突然多出几十次保护。
分开之后，配额用完就固定不动，统计值继续正常累加。

## 常见问题

**Q：玩家死了没保护，但背包还在？**
A：先查三件事 —— 那个世界是不是开了 `keepInventory`（那是原版规则，不是插件）、玩家有没有 `tinygrace.unlimited` 权限、`enabled` 是不是开着。

**Q：为什么改不了离线玩家的次数？**
A：数据存在玩家自身的 PDC 里，必须人在线才能写。这是「数据跟着玩家走」的代价，好处是换服/回档不丢。

**Q：玩家换服之后次数还在吗？**
A：在。数据跟着玩家存档走，只要他的玩家数据迁移过去，次数就一起过去。

**Q：能不能和极限生存类插件一起用？**
A：两个插件都会改死亡事件，建议先小范围测试。极限生存（一条命）和保护次数在语义上是冲突的，一般不会同时开。

**Q：`warn-at` 写 `[0]` 会怎样？**
A：不会多出提醒 —— 配额为 0 时的提醒由 `warn-exhausted` 控制，两个是独立机制。
